# 维护

## 改动边界

先确定改动属于播放器、音频调度、文字显示、歌曲数据还是制作工具。跨模块依赖通过参数传入。歌曲差异放进数据，并保留修改依据。

样式在所属组件的规则中维护。布局变化需要检查手机短屏、浏览器工具栏变化、假名、下一句以及歌词弹窗。播放按钮各状态保持相同的控件尺寸与位置。

修正时序问题时，保留最小复现：模式、速率、句子范围、操作顺序及发生时的原曲秒数。先确认音频来源和 session 映射，再检查词标注。修复定位到具体的播放会话、映射或标注数据，并覆盖对应切换路径。

## 测试

自动测试覆盖采样接点、短范围循环、长范围调度、输出延迟、断流停钟、过期 seek、取消、解码失败后备、倍速映射、均衡排版和数据校验。

自动测试验证调度逻辑；发布音频相关改动时，在浏览器和目标设备上检查：

- 全曲首次点击播放；暂停后继续；全曲循环。
- 逐句上一句/下一句、重播和循环，读音各档分别检查。
- 逐段循环，段落与逐句往返，范围边界处切换模式。
- 播放中拖动、连续拖动、切换三个速度、切歌。
- 限速或断网后恢复，确认字幕随音频一起暂停和恢复。
- iOS Safari 和添加到主屏后的首次播放、前后台切换、下一句及假名布局。

示例音调适合验证顺序和接点，真实歌曲的语音边界仍须试听。CI 使用本地夹具验证代码，歌曲导入和模型适配器在工作站上另行检查。

## Git 和发布文件

提交源码、测试、文档和文本示例。以下内容保持在忽略目录：歌曲和歌词、模型权重、模型响应、对齐日志、密钥、生成的网站及本机部署信息。

发布前检查 `git ls-files` 和差异，提交范围限定为公开源码、文档、测试与示例。个人部署配置、令牌保存在忽略目录；已跟踪文件需单独检查。

构建输出只保留播放器需要的展示字段，来源记录和审计记录保留在私有工作目录。歌曲内容按各自授权范围使用。

采用小而完整的提交：说明用户看到的行为、修改原因和验证方式。结论注明复现条件、测量范围和设备，供维护者复查。
