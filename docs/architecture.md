# 架构

歌曲制作由关联项目 Sorane Studio 负责，边界见[项目关系](relationship.md)。

## 运行路径

`main.js` 读取曲库，创建缓存、解码器、播放器和歌曲选择器。模块通过函数参数连接，各自维护状态和接口。

| 模块                                    | 职责                                        |
| --------------------------------------- | ------------------------------------------- |
| `player.js`                             | 播放意图、模式、选句、换源、进度和键盘交互  |
| `audio/transport.js`                    | 统一媒体元素、整段 PCM 和分块音频的播放接口 |
| `audio/chunks.js`                       | 按采样调度、预取、内存淘汰、断流恢复和循环  |
| `audio/decoder.js`                      | 无分块资源时的整段解码后备路径              |
| `audio/cache.js`                        | 压缩文件的持久缓存、并发下载合并和失效处理  |
| `audio/mixer.js`                        | 音频上下文解锁、四声道拆分和人声增益        |
| `timeline.js`                           | 原曲秒数到已变速录音秒数的换算              |
| `lyrics.js`、`furigana.js`、`layout.js` | 歌词文字、读音和均衡排版                    |
| `directory.js`、`library.js`            | 歌词目录、歌曲搜索和本地收藏                |

播放器状态集中在一个控制器。界面选择与正在发声的来源可以暂时不同，因此 `playbackSession` 单独记录歌曲、起点、速率和来源代号。音频位置与界面高亮均读取当前播放会话。

## 唯一时间基准

曲库里的句子和词使用原曲绝对秒数。速率为 `r` 的预制音频中，原曲位置 `t` 位于 `t / r`。例如 0.75 档的第 30 秒对应原曲 22.5 秒。

音频源用 Web Audio 的采样时钟调度。字幕在动画帧中读取同一个源的 `snapshot()`，按音频位置绘制高亮。支持输出时间戳的浏览器使用 `getOutputTimestamp()`，否则使用 `AudioContext.currentTime`。设备同步效果还受蓝牙及浏览器输出延迟影响，需结合目标设备测量。

拖动、切歌和换速增加请求代号。解码与 seek 完成后核对代号，仅接续当前会话。网络断流时字幕时钟停在已调度音频的末尾，恢复后继续。

## 分块和缓存

采样率为 44100 Hz。AAC 打包时每块主区间为 344 × 1024 帧，前后各保留最多 4096 帧，接点交叉淡化 1024 帧。接点由索引中的绝对帧数、裁切和解码长度计算。

每块有两个立体声文件：伴奏和人声。解码后组合为四声道。浏览器将四声道作为伴奏和人声两条可调立体声轨处理。AAC 解码的 1024 帧 priming 差异会在长度验证后归一化；不符合索引则转用整段解码。

长范围预取约 16 秒；20 秒以内的练习范围拼成一个原生循环缓冲。已解码块缓存目标为 32 MiB；整段后备缓存目标为 192 MiB。缓存按目标大小淘汰闲置数据，播放中的缓冲保留到使用结束；总内存还包括正在使用的缓冲。

压缩文件通过 Cache Storage 保留，目标为 512 MiB。构建输出用文件内容哈希命名，音频更新后使用新地址，缓存按版本区分资源。浏览器可能拒绝持久存储或回收缓存；刷新时优先读取已缓存的压缩文件，再按播放位置解码。

## 预览服务

Python 标准库服务提供构建目录中的网页和音频资源。静态托管平台可直接发布同一份构建结果。
